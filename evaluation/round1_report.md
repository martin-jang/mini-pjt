## 3. 실패 원인 분석

| 원인 | 케이스 | 설명 |
|---|---|---|
| **A. 생성 파이프라인 미구현** | #5, #3, #19 | #5는 POC 생성 자체가 없어 생성 경로·빌드 결과·흐름 검증 결과를 줄 수 없습니다(`status=partial`로 정직하게 응답). #3·#19는 공통 컴포넌트가 아직 없어 근거 문서가 없고, "근거 없음"으로 답했습니다. 응답 자체는 정책대로이지만 기대 특성을 충족하지 못했습니다. |
| **B. 근거 없음 응답이 너무 짧음** | #6, #7 | 지어내지 않고 "근거를 찾을 수 없습니다"라고 답한 것은 맞습니다. 하지만 기대 특성인 **수집된 화면 범위 안내**와 **대체 행동 제안**이 없습니다. 근거가 없으면 모델을 부르지 않는 구조라 고정 문구 한 줄로 끝났습니다. |
| **C. 덮어쓰기 승인 순서** | #14 | 승인은 요청했지만 Happy Path 확인(H3)이 덮어쓰기 확인(H4)보다 먼저 나와서, 응답에 "어떤 결과물을 덮어쓰는지"가 없습니다. 게다가 이번 실행 시점에는 기존 결과물 폴더가 없어 H4 자체가 나오지 않습니다. |

RAGAS 관찰:
- **answer_relevancy 0.411이 가장 낮습니다.** 답변이 길고 근거·출처·부연을 많이 붙입니다. 이 지표는 답변에서 질문을 역생성해 비교하기 때문에 장황할수록 점수가 떨어집니다.
- **context_recall 0.55**: 정답 문장에 있는 세부 사실(예: #2의 제출 버튼명·로그인 필요 여부, #4의 화면별 변이 위치)이 검색된 4개 문서에 다 들어 있지 않은 경우가 있습니다.
- **#15 context_precision 0.25**: 정답 화면(계좌 활동 내역) 외에 관련 낮은 문서가 상위에 같이 올라옵니다.

## 5. 측정의 한계

- 판정은 LLM-as-Judge라 같은 응답도 실행마다 판정이 흔들릴 수 있습니다. 실패 케이스는 모두 판정 사유를 열어 직접 확인했고, 위 원인 분석과 일치합니다.
- 평가는 ParaBank 스냅샷과 합성 픽스처 2개 대상 기준입니다. 실제 고객 레거시로의 일반화는 측정하지 않았습니다.
- L2 필드 recall 100%는 정답 필드가 같은 스냅샷 추출에서 나온 값이라 참고용입니다. 변이 그룹·통일 결정 정답은 주입한 변이 목록에서 독립적으로 만들어졌습니다.
- 질의 케이스 응답 시간은 5~9초, 분석(#1)은 47.5초였습니다(인벤토리·통일 결정·Happy Path·재적재 포함).
