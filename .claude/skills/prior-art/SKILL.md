# Prior art 먼저

제안을 직접 지어내기 전에, 같은 문제를 이미 잘 푸는 **prior art**(널리 쓰이는 오픈소스 스킬·라이브러리·플러그인)를 찾아 "이걸 적용해 봐도 좋다"고 먼저 제시한다. 자체 제안은 그 다음이다.

## 단계

1. **문제 정의**: 요청을 도메인 문제 한 줄로 바꾼다 (예: "레거시 화면 변이 클러스터링", "React 공통 컴포넌트 문서화"). 문제가 여러 개면 각각 따로 찾는다.
   - 완료: 검색어로 쓸 문제 문장이 정해졌다.

2. **찾기**: 아래 출처를 순서대로 확인한다.
   - 이미 설치된 스킬·플러그인 (세션에 나열된 스킬 목록)
   - Claude Code 플러그인 마켓플레이스, 공개 스킬 저장소
   - GitHub, npm, PyPI — 웹 검색으로 실제 페이지를 확인한다
   - 완료: 출처마다 확인했고, 후보마다 이번 세션에서 직접 확인한 **채택 근거**(GitHub 스타, 주간 다운로드, 최근 릴리스 날짜, 라이선스)와 링크가 있다. 기억에만 의존한 수치는 쓰지 않는다.

3. **선별**: 채택 근거가 약하거나(오래 방치, 사용자 적음) 프로젝트 스택(CLAUDE.md의 기술 스택)과 맞지 않는 후보는 뺀다. 2~4개로 줄인다.

4. **보고**: 자체 제안보다 먼저 아래 표로 보여준다.

   | 후보 | 푸는 문제 | 채택 근거 | 우리 프로젝트 적합도·한계 | 시도 방법 |
   |---|---|---|---|---|

   이어서 추천 하나를 고르고 이유를 적는다. 그 다음에 자체 제안을 쓰되, 어느 후보를 쓰는지(또는 왜 직접 만드는지) 밝힌다.
   - 적합한 prior art가 없으면, 무엇을 어디서 찾았는지 한 줄로 적고 자체 제안으로 간다.

5. **적용은 확인 후**: 설치·의존성 추가·코드 반영은 사용자가 고른 뒤에 한다.
